# api/: backend ajan kuralları

.NET 10 modüler monolit, PostgreSQL 17, EF Core 10, NodaTime. Önce kök [AGENTS.md](../AGENTS.md)'yi okuyun.

Zorunlu okuma: [docs/mimari/mimari.md](../docs/mimari/mimari.md), [docs/standartlar/kodlama-dotnet.md](../docs/standartlar/kodlama-dotnet.md), [docs/standartlar/test-stratejisi.md](../docs/standartlar/test-stratejisi.md). İşe göre: `docs/alan/*`, ilgili ADR.

## Yapı
```
api/
  Omvila.slnx  global.json  Directory.Build.props  Directory.Packages.props  BannedSymbols.txt  .editorconfig
  src/Omvila.Host/                     # Program.cs; --role=api|worker|all|migrate|seed
  src/Omvila.SharedKernel/             # Result, Error, ErrorCodes, Money, PhoneNumber, Ids, IClock, IIdGenerator
  src/Omvila.Infrastructure/           # bağlantı + transaction, RLS kurulumu, outbox, iş zamanlayıcı, idempotency, dış servis adaptörleri
  src/Modules/<Modül>/Omvila.Modules.<Modül>/            # Domain/ Features/ Infrastructure/ Jobs/ IntegrationEventHandlers/
  src/Modules/<Modül>/Omvila.Modules.<Modül>.Contracts/  # public arayüzler + olaylar
  tests/Omvila.Modules.<Modül>.Tests/                    # alan + handler birim
  tests/Omvila.Modules.<Modül>.IntegrationTests/         # Testcontainers
  tests/Omvila.ArchitectureTests/  tests/Omvila.Api.ContractTests/  tests/Omvila.TestKit/
```
Modüller: Identity, Tenancy, Catalog, Customers, Scheduling, Sales, Reviews, Notifications, Integrations, Platform. Hangi varlık hangi modülde: [alan-modeli.md § Modüller](../docs/alan/alan-modeli.md#modüller).

## Yeni bir uç nokta eklerken (sıra)
1. Uç `contracts/openapi.yaml`'da mı? Değilse önce oraya ekleyin ([contracts/AGENTS.md](../contracts/AGENTS.md)).
2. Modülü belirleyin. Klasör: `Features/<FiilIsim>/`.
3. Alan kuralı varsa önce `Domain/` testini yazın, sonra aggregate metodunu.
4. `Request`/`Response` kayıtlarını sözleşmedeki şemayla **aynı adlar ve tiplerle** yazın (camelCase JSON, enum metin).
5. Handler: yükle → alan metodu → kaydet → eşle. Yan etki = entegrasyon olayı veya outbox satırı.
6. Endpoint: `.WithName("<operationId>")`, `.RequirePermission(...)` veya `.AllowAnonymous()` + gerekçe yorumu, gerekiyorsa `.RequireIdempotencyKey()` / `.RequireIfMatch()`.
7. Entegrasyon testi: mutlu yol, 403, 404 (başka marka), iş hatası kodları. Sözleşme testi otomatik koşar.
8. Migration (gerekiyorsa): RLS politikası, indeks (`brand_id` önce), CHECK kısıtları.

## Kesin kurallar
- Katman ve modül sınırları: [mimari.md § Katman kuralları](../docs/mimari/mimari.md#katman-kuralları-mimari-testlerle-zorlanır). İhlal mimari testte kırılır.
- Kiracı bağlamı JWT'den gelir. İstek gövdesinden veya başlıktan `brandId` okunmaz.
- Durum yalnız aggregate metoduyla değişir. Geçiş tablosu: [durum-makinesi.md](../docs/alan/durum-makinesi.md). Her geçiş için test.
- Randevu yazma yolu: kilitler (sıralı) → süresi dolmuş tutmaları iptal → müsaitliği yeniden hesapla → yaz → outbox → commit. `23P01` → `slot_taken`. Ayrıntı: [musaitlik.md](../docs/alan/musaitlik.md). Uygulaması `AppointmentWriter` (Scheduling `Features/Appointments`): uçlar randevuyu yalnız onunla yazar veya saatini değiştirir; kilit zaman aşımı `Error.Unavailable()` → 503 `try_again`.
- Zaman `IClock`; kimlik `IIdGenerator`; para `Money`; telefon `PhoneNumber`.
- Hata kodları yalnız `ErrorCodes` sabitlerinden; yeni kod önce sözleşmeye.
- Ayar ve süre sabitleri `PlatformDefaults` içinde, her biri `sureler-ve-ayarlar.md` satırına atıfla.
- Dış servisler (`ISmsSender`, `IPushSender`, `IEmailSender`, `ICalendarProvider`, `IFileStorage`) arayüz arkasında. Geliştirme ve testte sahte uygulama (`Fake*`). Sahte SMS mesajları `infra.dev_sms_log` tablosuna yazar (metin konsola yalnız Development'ta; test sunucusunda `/dev/sms`, [test-ortami.md](../docs/mimari/test-ortami.md)).
- MediatR, AutoMapper, Hangfire, EF InMemory, SQLite kullanılmaz.

## Komutlar
`dotnet test` komutları `api/` içinden çalışır: test platformu (Microsoft.Testing.Platform) ayarı `api/global.json`'dadır; depo kökünden çalıştırılırsa eski VSTest kipine düşer.
```bash
docker compose up -d postgres                                  # kökten (api/db/init rol betiği ilk açılışta çalışır)
cd api
dotnet tool restore                                            # dotnet-ef (dotnet-tools.json)
dotnet run --project src/Omvila.Host -- --role=migrate         # migration'ları omvila_migrator ile uygular ve çıkar (eski biçim: -- migrate)
dotnet build Omvila.slnx -warnaserror
dotnet test --solution Omvila.slnx --filter-not-trait "Category=Integration"   # hızlı
dotnet test --solution Omvila.slnx                                             # tümü (Docker gerekir)
dotnet format Omvila.slnx --verify-no-changes
dotnet run --project src/Omvila.Host -- --role=all             # http://localhost:5080
dotnet ef migrations add <KisaAciklama> -p src/Modules/Scheduling/Omvila.Modules.Scheduling -c SchedulingDbContext -o Infrastructure/Migrations   # EF zaman damgasını ekler
scripts/export-openapi.sh && oasdiff diff ../contracts/openapi.yaml artifacts/openapi.json --fail-on-diff
```

## Veritabanı erişimi
- Uygulama `omvila_app` rolüyle bağlanır (RLS'e tabi, tablo sahibi değil); migration `omvila_migrator` ile çalışır (ADR-0001). Roller `api/db/init/01-roles.sql`'de; docker-compose ve Testcontainers aynı betiği kullanır.
- Her API ucu `MapApiGroup(...)` grubunda tek transaction'da çalışır. Oturumu `UseOmvilaDbSession()` ara katmanı kimlik doğrulamadan sonra ve parametre bağlamadan önce açar (uç parametreleri filtrelerden önce çözülür); `TransactionEndpointFilter` başarılı sonucu yanıt yazılmadan commit eder, 4xx/5xx ve istisnada rollback. İş (worker) oturumunu `JobRunner` açar.
- Kiracı bağlamı `IDbSession.SetTenantAsync(TenantScope...)` ile kurulur ve `set_config(..., true)` ile yalnız o transaction'a uygulanır.
- Modül DbContext'i `services.AddModuleDbContext<T>("schema")` ile kaydedilir; ilk migration `GrantSchemaUsageToApp`, markaya ait her tablo `EnableTenantIsolation` çağırır. `RlsGuardTests` politikasız `brand_id` tablosunda düşer.
- Testler: `Omvila.TestKit` (`PostgresFixture`, `TestClock`, `RlsGuard`). Veritabanı testleri `[Trait("Category", "Integration")]` ve `[Collection(PostgresTests.Name)]` taşır.
- **Kimlik ve yetki (ADR-0007):** API grubu yüzeyini bildirir: `app.MapApiGroup("/api/v1/manage", Audiences.Manage)`; bir yüzeyin jetonu diğerinde geçmez. Her uç ya `.RequirePermission(Permissions.X.Y)` ya `.AllowAnonymous()` + gerekçe yorumu taşır (`EndpointAuditTests` işaretsiz ucu yakalar). İzin yoksa 403; jeton yok veya geçersizse 401 `unauthorized`, süresi dolmuşsa 401 `token_expired`. Kiracı bağlamı jetondan kurulur (`brand_id`); kapsam (Ş/K) sorguda `IPermissionResolver` ile uygulanır. İzin matrisi `RolePermissions` (belgeyle testle eşli). İmza anahtarları `Auth:SigningKeys` (kasadan); Development'ta yoksa geçici anahtar, Staging/Production'da eksikse açılış durur (`IdentitySecretsValidator`, T-73).
- **Yenileme jetonu:** `RefreshTokenService` (Issue, Rotate, RevokeFamily). Yalnız SHA-256 özeti saklanır; her kullanımda döndürülür, ömür baştan başlar (`Auth:RefreshTokenDays*`). Kullanılmış jeton yeniden gelirse aile ayrı transaction'da iptal edilir. Web'de çerez `RefreshTokenCookie` (`omvila_rt`, HttpOnly, Secure, SameSite=Strict, Path=/api/v1/manage/auth; hatırla → kalıcı), çerezle yenilemede `X-Requested-With` zorunlu (`XRequestedWithFilter`).
- **CORS (T-60):** `MapApiGroup` ön ekten yüzeyi bulur (`ApiSurface`: manage, admin, me, public) ve `cors:<yüzey>` politikasını bağlar; kökenler `Cors:Surfaces:{Manage|Admin|Me|Public}:Origins` (joker, yol ve Development/Testing dışında http başlangıçta reddedilir; Staging ve Production'da ortamdan). Kimlik bilgisi (çerez) yalnız manage ve public'te; ETag, Location, Idempotent-Replayed, Retry-After açığa çıkar. `UseSurfaceCors()` kimlik doğrulama ve hız sınırından önce: ön uçuş jetonsuz yanıtlanır. Yeni istemci başlığı `SurfaceCorsExtensions.AllowedHeaders`'a eklenir.
- **Sabit değerler:** platform varsayılanları `SharedKernel/PlatformDefaults` içinde, her biri `sureler-ve-ayarlar.md` satırına atıfla (ör. `SlugRedirectDays`). Ortama göre değişen teknik ayarlar appsettings'te.
- **Testte migration:** `PostgresFixture` bütün modüllerin migration'larını uygular; yeni modül TestKit'e ve `InitializeAsync`'e eklenir.
- **OTP:** `OtpService.RequestAsync(phone, purpose)` ve `VerifyAsync(otpId, code, purpose)`; istek transaction'ı içinde. Kod HMAC-SHA256 (amaç ve telefon özete bağlı) saklanır, `otp.code` bildirimiyle gider. Kurallar ve süreler `Auth:Otp` (sureler-ve-ayarlar.md): bekleme amaç başına, saatlik sınır ve kilit telefon başına. Yanlış deneme sayacı ayrı transaction'da yazılır (4xx rollback'ten etkilenmez). HMAC anahtarı `Auth:Otp:HmacKey` (kasadan); Development ve Testing'de yoksa geçici, Staging/Production'da eksikse açılış durur.
- **Kapora hesabı ve IBAN (T-78):** `Iban` (SharedKernel; maske `TR29 •••• 6789 01`, `ToString` maskeli). `tenancy.brand_bank_accounts` markada tek satır; IBAN `IbanProtector` ile AES-256-GCM şifreli (marka kimliği ek veri), anahtar `Tenancy:IbanEncryptionKey` (base64 32 bayt, kasadan); Development ve Testing'de yoksa süreç başına geçici, Staging/Production'da eksikse açılış durur (`TenancySecretsValidator`). Diğer modüller aktif hesabı `IBrandBankAccounts` (Tenancy.Contracts) ile okur; tam IBAN yalnız müşterinin havale bilgisinde döner, günlüğe yazılmaz.
- **Kapora çözümü (T-81):** kalem kaporası Catalog `IServiceDeposits` (politika, eşik, aktif hesap `ITenantQueries.GetDepositSettingsAsync`); online oluşturmada `CreateAppointmentCommand.Deposit` (`DepositTerms`) verilir, `AppointmentWriter` plandan çözer ve açıklama kodunu `TransferCodeGenerator` ile üretir (marka içinde benzersiz indeks, çakışmada yeni kod). Havale talimatı (`DepositInstructionsView`) randevuda kopyalanmaz, her okumada güncel aktif hesaptan.
- **Kapora geldi ve tahsilat (T-82):** Sales modülü (`sales` şeması: `Payment`, `PaymentAllocation`). "Kapora geldi" (`DepositReceipts`, Scheduling `Features/Deposits`) tahsilatı Sales.Contracts `IDepositPayments.RecordDepositAsync` ile aynı istek transaction'ında yazar, sonra randevuyu günceller ve `AppointmentDepositReceived` yayımlar (Notifications: `deposit.received` SMS'i + hatırlatmalar). "Kaporasız onayla" `Approve(..., waiveDeposit)`; kapora bekleniyorken bayraksız onay 409 `deposit_required`.
- **Kapora takibi (T-83):** `DepositFollowUps` (Scheduling `Features/Deposits`): "Havaleyi yaptım" (`ReportDepositTransfer`, kendiliğinden idempotent, ilk bildirimde `AppointmentDepositReported` → `staff.deposit_reported` push + panel, alıcı `appointment.deposit.mark`), "Hatırlat" (V6; kontör `ICreditLedger.GetBalanceAsync` ile işaretten önce, `AppointmentDepositReminded` → `deposit.awaiting` yeniden) ve "Salon iade etti" (V7; `IDepositPayments.MarkDepositRefundedAsync` aynı transaction'da, randevuda `DepositRefunded*`, not yalnız panel geçmişinde). A5 kaporalı iptalde `deposit.not_received` (`DepositSms`), salon iptalinde kapora alınmışsa `cancelled_by_salon` çeşidi `deposit_received`.
- **Değerlendirmeler (T-89):** Reviews modülü (`reviews` şeması: `Review`, `ReviewInvitation`). /d/ kodu Scheduling'de (`AppointmentAccessCode` Purpose Review); Reviews onu Scheduling.Contracts `IAppointmentReviewLinks` ile üretir ve çözer (kod çözümü /r/ gibi platform bağlamında, sonra markaya geçer). Davet `IReviewInvitations.ScheduleAsync` (Reviews.Contracts) → `ReviewInviteScheduled` → Notifications `review.invite` (tamamlanma + `ReviewInviteDelayMinutes`, Push → SMS); `AppointmentCompleted` işleyicisi tamamla ucuyla (T-88) bağlanır. Gönderim `ReviewReceived` → `staff.review_received` (alıcı `review.view`; personel almaz, W8). Rezervasyon puanı Tenancy'de `IReviewRatings` ile (eşik `ReviewPublicThreshold`, `showReviews`).
- **Bildirim ve SMS:** bildirim `INotificationOutbox.EnqueueSmsAsync(new SmsNotification(NotificationEvents.X, phone, values, brandId))` ile iş transaction'ında yazılır; `DispatchNotifications` işi şablonla oluşturup `ISmsSender` ile gönderir. Doğrudan SMS gönderilmez. Şablon metinleri `SmsTemplates`'te, `bildirimler.md` ile birebir; her şablon en uzun değerle 155 birim sınırında test edilir. Sağlayıcı `Sms:Provider`: şimdilik yalnız `Fake` (T-03), o da yalnız Development ve Testing'de, test sunucusunda (Staging) yalnız `Staging:AllowFakeProviders=true` iken (T-73); mesajlar `infra.dev_sms_log`'a yazılır (metin günlüğe yalnız Development'ta, `AllowsSmsContentInLogs`). Randevu SMS'leri Notifications'taki olay işleyicilerinden (`IntegrationEventHandlers/`) yazılır; zamanlanmış satır `SmsNotification.ScheduledUtc`, bağlı kayıt `Reference`, ikinci metin `Variant`; bekleyen hatırlatmalar `CancelPendingAsync` ile düşer (T-53). Gönderim (T-64): salon mesajı parça sayısı (`SmsEncoding`) kadar kontör düşer, düşüm ve `Sent` aynı transaction'da, marka defteri `CreditLedger.LockBalanceAsync` ile kilitli (bakiye = `SUM(amount)`); yetmezse `Skipped`/`insufficient_credits` + `SmsCreditsInsufficient` olayı, eşik altına inişte `SmsCreditsLow`. OTP OMVILA'dan ve `OMVILA` adıyla; diğerleri `BrandSmsSender.EffectiveName`. Geçici hata üstel geri çekilmeyle (`Notifications:RetryBaseDelaySeconds`, `RetryMaxDelaySeconds`, `MaxAttempts` 5). Teslim raporu `POST /api/v1/webhooks/sms/{provider}`: adaptör keyed `ISmsDeliveryReportVerifier` (imza ham gövde üzerinden), sahte sağlayıcının gizlisi `Sms:Providers:fake:WebhookSecret`.
- **Push (T-66):** `IPushSender` (Infrastructure/Push); `Push:Provider` boş → kapalı, `Fake` yalnız Development/Testing ve izinli Staging (T-73), `Fcm` (`Push:Fcm:ProjectId`, `Push:Fcm:CredentialsJson` kasadan/ortamdan) kimlik bilgisi yoksa kapalı. İşletme push'u `INotificationOutbox.EnqueueStaffPushAsync(new StaffPushNotification(...))` (alıcıları çağıran seçer; sessiz saatte sabaha ertelenir, `QuietHours`); metinler `PushTemplates` (≤ 40 / 90 karakter). Müşteri mesajında `SmsNotification.CustomerId` verilirse plan [Push, Sms]: cihaz yok, push kapalı veya başarısızsa aynı çalışmada SMS. İşletme push'u SMS'e düşmez (cihaz yoksa `Skipped`/`no_device`). Geçersiz jetonlu cihaz pasifleşir. Cihaz kaydı `POST /api/v1/manage/devices` (`notifications.devices`). Jeton, telefon ve push metni günlüğe yazılmaz.
- **Bildirim paneli ve ayarlar (T-71):** işletme olayı işleyicisi alıcıları `IBrandUserDirectory.GetUserIdsWithPermissionAsync(marka, izin, şube?)` ile seçer, panel kaydını `InAppNotifier.AddAsync` (`notifications.in_app_notifications`, metin push şablonundan, müşteri adı tam) ve push'u `EnqueueStaffPushAsync` ("Ad S.") ile yazar. Hatırlatma zamanları ve değerlendirme daveti `tenancy.brand_settings`'te; kanonik uç `brand/notification-settings` (Tenancy), Notifications `ITenantQueries.GetNotificationSettingsAsync` ile okur.
- **Uç eşleme:** modül uçları `Map<Modül>Endpoints()` ile Host'ta eşlenir; istek ve yanıt kayıtları sözleşmedeki şemanın birebir karşılığıdır. JSON: camelCase, enum metin, boş isteğe bağlı alan yazılmaz. İzin gerektirmeyen oturumlu uç `.RequireAuthenticated(Audiences.X)`.
- **HTTP eşlemesi:** uç `return result.ToHttp(r => TypedResults.Ok(r));` ile biter; hata `Error.ToProblem()` ile problem+json olur (code, errors, meta). Veritabanı hataları `DatabaseExceptionHandler`'da eşlenir: eşzamanlılık → 412, `23P01` → `slot_taken`, kayıtlı benzersiz indeks → `services.AddUniqueConstraintError("ix_…", ErrorCodes.…)`. Kayıtsız 23505 → 500.
- **Eşzamanlı düzenleme:** düzenleme ve durum uçları `.RequireIfMatch()`; handler sürümü `httpContext.GetIfMatchVersion()` ile alır (xmin). `GET` yanıtı `ETag: ETagVersion.Format(xmin)` döner.
- **Idempotency:** kaynak oluşturan ve para kaydeden POST'lar `.RequireIdempotencyKey()`. Aynı anahtar + aynı istek ilk başarılı yanıtı döner (`Idempotent-Replayed: true`); farklı istek 422 `idempotency_key_reused`. Kayıt kiracı kapsamlıdır, iş verisiyle aynı transaction'da yazılır; hata sonuçları saklanmaz. Saklama süresi `Idempotency` ayarlarında, `PurgeIdempotencyKeys` siler.
- **Outbox (ADR-0005):** yan etkiler `IOutbox.EnqueueAsync(new XHappened(...))` ile iş transaction'ında yazılır. Olay `IIntegrationEvent` uygulayan bir record'dur (modülün Contracts projesinde) ve markaya aitse `BrandId` taşır. İşleyici `IIntegrationEventHandler<T>`, kayıt `services.AddIntegrationEventHandler<T, THandler>()`. İşleyici kendi transaction'ında çalışır ve kiracı bağlamını olaydan kurar; aynı olay için ikinci kez çağrılmaz. Hata olursa yalnız o işleyici geri çekilmeyle yeniden denenir (`Outbox` ayarları appsettings'te).
- **Periyodik işler:** `IPeriodicJob` (`Key`, `RunAsync`), kayıt `services.AddPeriodicJob<TJob, TOptions>(o => Duration.FromSeconds(o.XIntervalSeconds))`: aralık işin üyesi değildir, kayıtta ayardan seçilir; `JobHostedService` onu açılışta işi oluşturmadan ve veritabanına bağlanmadan okur (iş kurucusundaki DbContext ancak `JobRunner`'ın başlattığı oturumda çözülür; T-77). Ayar eksik/geçersizse veya bir döngü beklenmedik biterse Critical günlük + servis hata ile biter (host durur); tur hatası (veritabanına ulaşılamıyor, iş istisnası) Error günlük + sonraki turda yeniden dener. Yalnız worker rolünde zamanlanır; advisory lock ile tek örnekte çalışır, sonucu `infra.job_runs`'a yazılır. `JobRunner` işi platform kapsamlı açık bir transaction'da çözer: iş DbContext'i kurucudan alır, oturumu kendisi başlatmaz veya commit etmez; başarıda commit, istisnada rollback. Testte `JobRunner.RunOnceAsync(typeof(T))` ile doğrudan çağrılır, saat `FakeClock` ile ilerletilir.
- **Ortamlar (T-73):** Development (yerel), Testing (otomatik testler), Staging (test sunucusu, gerçek kişi verisi yok), Production. Ortam koşulu yalnız `Infrastructure/Hosting/HostEnvironmentExtensions`'ta (`IsDevelopmentOrTesting`, `AllowsFakeProviders`, `AllowsDemoData`); başka yerde `IsEnvironment(...)` yazılmaz. Sahte sağlayıcı izni `FakeProviderOptionsValidator` ile açılışta denetlenir. `appsettings.Staging.json` yalnız gizli olmayan varsayılanları taşır; gizli değerler ortam değişkeninden.
- **Sahte SMS günlüğü (T-76):** `GET /dev/sms` (`Infrastructure/Sms/DevSmsLogPage`) sahte sağlayıcının `infra.dev_sms_log` kayıtlarını HTML olarak gösterir (en yeni üstte, `Sms:DevLog:Limit`, `?telefon=` süzgeci, Europe/Istanbul). Sözleşmede ve OpenAPI'de yok. Yalnız sahte SMS sağlayıcısı etkinken eşlenir; Production'da yol yoktur. **Kimlik doğrulaması yoktur:** test sunucusunda koruma Caddy basic auth'tadır (`sms.test.omvila.com.tr`); bu yol vekilsiz dışarı açılmaz.
- **Ters vekil (T-76):** `UseTrustedForwardedHeaders()` hattın başında; `X-Forwarded-For`/`X-Forwarded-Proto` yalnız `ForwardedHeaders:KnownProxies` (IP) veya `ForwardedHeaders:KnownNetworks` (CIDR) kaynağından kabul edilir, ikisi boşsa (Development, Testing) hiç işlenmez. IP başına hız sınırı `Connection.RemoteIpAddress` okur; başlığı kendiniz ayrıştırmayın.
- Yerelde 5432'de başka bir PostgreSQL çalışıyorsa `localhost` ona gider; `ConnectionStrings__Default/Migrator` ile portu değiştirin.

Kapora bekleyen ikisi seed'den 2 saat sonra otomatik iptal olur (`deposit.not_received` SMS'i). IBAN şifreli yazıldığından Testing dışında `Tenancy:IbanEncryptionKey` zorunludur ve API aynı anahtarla çalışmalıdır: `export Tenancy__IbanEncryptionKey="$(openssl rand -base64 32)"` (seed ve `--role=all` aynı kabukta). İdempotent: marka varsa bir şey yazmaz. `-- --role=seed --reset` yalnız demo markasını (sahibin telefonuyla tanınır) her modülün `IBrandDataEraser`'ı ile silip yeniden kurar; tarihler çalıştırma anına göre olduğundan demo öncesi önerilir. Yalnız Development, Staging ve Testing; Production'da hata ile çıkar. Kod `Host/Seeding` (içerik `DemoDataSet`) ve modüllerin `DemoData/` klasörleri; randevular `AppointmentWriter` ile, kapora tahsilatı Sales.Contracts `IDepositPayments` ile, olay yazılmaz (SMS üretmez). `--reset` Sales dahil her modülün tablolarını siler.
